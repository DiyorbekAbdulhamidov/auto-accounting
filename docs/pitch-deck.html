Where it ends up

Bank records and e-invoice records feed the same VAT return. When they disagree, the difference is not an internal inconvenience — it becomes a reporting discrepancy in front of the tax authority.

The work is slow, repetitive and done under deadline. That is exactly the kind of work software should be doing.

What makes it different

Not a viewer. An audit tool.

06
=

The balance equation

Opening balance + credit − debit must equal the closing balance. If a bank export has debit and credit swapped, the file's own total still adds up — this check does not.

!

Category protection

Utility and treasury lines are set aside but never deleted — the grand total always stays complete. The system refuses to classify a counterparty on its own; it warns instead.

↺

Shared format memory

An unfamiliar bank layout is learned once and recognised afterwards. The memory is shared, so every new user strengthens the system for everyone else.

The design rule behind all three: the two kinds of mistake do not cost the same. Showing one extra row is visible and harmless. Hiding one real row makes money disappear silently — so the system is built never to do the second.

Why the limit is on companies, not reconciliations. An accountant does not reconcile once — they upload, see a gap, fix the source file and upload again. Counting reconciliations would charge the user for the product working properly.

Where the price came from. The first figure was an estimate. It was replaced after asking a practising accountant what they would actually pay. At this stage volume is worth more than revenue: every new user brings a new bank format into the shared memory.
